## 五、重要澄清：U-01 / EC-03「主键冲突」不存在

前序记录长期挂着「D7 主键为 INTEGER 自增、D8 举例为 UUID」的所谓冲突，并多次列为最高优先级待决。

**本轮逐字重读 D7 §9.1 DDL 后实测：D7 已明确 `image_asset.id` 与 `recognition_record.id`
为 TEXT(36) UUID**，`user`/`species`/`operation_log` 为 INTEGER 自增，`system_config` 与
`guest_usage` 为 TEXT 主键 —— **主键类型不统一是有意设计，且与 D8 举例完全一致**。

**结论：不存在文档冲突，是早期记忆有误。该项无需裁决，可直接关闭。**

## 六、本轮修复的真实缺陷

| # | 缺陷 | 严重度 | 根因 | 修复 |
|---|---|---|---|---|
| 1 | `create_all` 静默失败，`Base.metadata` 表数为 0 | 🔴 严重 | 以脚本运行 `database.py` 时它成为 `__main__`，而 `app.models` 的 `from app.core.database import Base` 会**再导入一份**，内存中出现**两个不同的 `Base` 类** | 移除 `database.py` 的 `__main__` 建表逻辑，改独立入口 `backend/scripts/init_db.py` |
| 2 | `query.args / query.kwargs: Field required`（40001，全端点阻塞） | 🔴 严重 | `dependencies=[Depends(RateLimited)]` 把已是 `Annotated[None, Depends(fn)]` 的别名**再套一层** `Depends()`，FastAPI 无法内省 | 新增 `RATE_LIMIT_DEP = [Depends(enforce_rate_limit)]`，直接放原始函数 |
| 3 | `is_locked()` 报 `'int' object has no attribute 'tzinfo'` | 🟠 中 | 按 `datetime` 语义写，但 D7 定义 `locked_until` 为 INTEGER 时间戳 | 改 `_now_ts()` 时间戳运算 |
| 4 | `/api/health` 永远 `ready=False` | 🟠 中 | `describe()` 不触发懒加载，模型首次推理才加载 | `describe(try_load=True)` 默认尝试加载 |
| 5 | `models/__init__.py` 与 D7 DDL 13+ 处不符 | 🟠 中 | 早期按错误记忆写字段名/类型 | 逐字对齐 D7 §9.1 整套重写 |

## 七、工具链陷阱（复用价值高）

1. **FastAPI 0.141.1**：`include_router` 生成 `_IncludedRouter` 包装对象，
   **不再扁平化进 `app.routes`** → 核对端点须用 `app.openapi()['paths']`，
   否则会误判为"只挂载了 2 个端点"。
2. **SQLAlchemy inspector 无法反射表达式索引**（如 `LOWER(username)`）——
   静默跳过且只发 SAWarning，索引其实已建成却读不到。
   **核对索引必须直查 `sqlite_master`**（`sql IS NOT NULL` 计显式索引）。
3. **`TestClient.delete()` 不接受 `json=`** → 改用 `c.request('DELETE', url, json=..., headers=...)`。
4. **测试隔离**：`settings` 是模块级单例，且 `security`/`database` 用
   `from app.core.config import settings` **提前绑定了引用** —— 仅改 `_cfg.settings` 无效，
   必须**原地 `setattr` 更新对象属性** + `importlib.reload()` 相应模块。
5. **`urllib` 把响应头名规范为小写** → 直查 `dict(r.headers)['X-Request-Id']` 会得 `None`，
   易误判为"响应头缺失"。须先 `{k.lower(): v for ...}`。
6. **限流不是缺陷**：`42902` 在探测时触发属正常行为，脚本须主动节流/退避。
