**文档版本**：V1.0

## 一、任务总览

### 1.1 项目定位

基于 CNN 的海洋鱼类图像分类 Web 应用：用户上传水下鱼类图像后，系统自动识别物种（23 类）、给出置信度与 Top-5 候选，并展示物种介绍。性质为**模型接入 + 迁移学习 + 应用工程化**，非从零训练研究型项目。

### 1.2 硬性验收指标

| 指标 | 目标值 | 实测值 |
| --- | --- | --- |
| 测试集准确率 acc | ≥ 85% | 0.9963 |
| 宏观 F1（macro F1） | ≥ 0.82 | 0.9678 |
| 单图端到端时延 | ≤ 3 s | p50 90.8 ms |
| 量化等优化精度回退 | ≤ 1 pp | 通过（未启用优化，维持基线） |

### 1.3 技术栈

- **前端**：React 18.3 + TypeScript 5.6 + Vite 6 + Tailwind CSS 3.4 + Ant Design 5.22 + Zustand 5 + Axios 1.7
- **后端**：Python 3.12+ / FastAPI / SQLite（7 表 64 字段）/ PyTorch
- **模型**：ResNet18 迁移学习，输入 224×224，23 类
- **端口约定**：前端 5180 / 后端 8000 / API 前缀 `/api` / 环境变量前缀 `SEATONG_`

## 四、关键决策记录

| 决策 | 结论 | 理由 |
| --- | --- | --- |
| 指标口径 | 以 macro F1 为核心难点 | 长尾分布下 acc 被头部类主导 |
| 长尾策略 | 维持基线（采样器），不加权/不去尾 | 对照实验证明两种长尾策略均无正收益 |
| 模型优化 | 不启用量化/剪枝 | 静态量化收益被「不得为优化而优化」约束排除；剪枝 1% 即崩 |
| OOD 强化 | 混合微调并替换生产模型 | 网图 Top-1 从 32.26% 提升至 82.80%，同分布无遗忘 |
| 他人资源错误码 | 统一 40401 | 防 ID 枚举，不返回 403 泄露存在性 |
| 上传与识别分离 | 两端点分离 | 上传不扣游客额度，提升试用体验 |

## 五、风险与应对（摘自 PRD 第 11 章）

| 风险 | 应对 |
| --- | --- |
| 长尾类别样本极少（最小类 14 张） | 薄弱类监控 + 低置信兜底提示 |
| 域偏移（水下→网图） | OOD 混合微调 + 冻结基准持续评估 |
| CPU 环境推理慢 | GPU 优先、CPU 自动降级；实测 CPU 前向 5.8 ms 远低于预算 |
| 端口冲突 | 前端改用 5180，避免与常用 5173 冲突 |
| SQLite 并发限制 | 单机教学场景足够；写操作短事务 |
