# 回答示例

**用户问**：海瞳鱼鉴的整体架构是什么样的？

**回答**：根据[系统架构与技术选型语料库](02-系统架构与技术选型语料库.md)，系统采用前后端分离架构，从上到下分为：

1. **前端展示层** - 基于 React 18.3 + TypeScript + Ant Design 5 开发（端口 5180），负责图像上传、识别结果展示、历史记录、用户与后台管理的可视化交互
2. **API 服务层** - 基于 FastAPI 框架（端口 8000，前缀 /api），包含 38 个端点，覆盖认证、上传、识别、历史、用户、游客额度、后台管理
3. **模型推理层** - ResNet18 迁移学习模型（输入 224×224，23 类），生产模型为 ml/models/M1_ood_tuned/best.pt
4. **数据存储层** - SQLite 数据库（7 表 64 字段）+ 本地文件系统存储图像，时间字段统一 INTEGER Unix 时间戳（UTC）

---

**用户问**：为什么识别准确率要用 macro F1，只用准确率不行吗？

**回答**：根据[模型训练与数据集实训语料库](10-模型训练与数据集实训语料库.md)，本项目数据集存在严重长尾失衡：27,324 张图像中头部 4 类占 82.1%，最小的 fish_21 类仅 14 张。

只用准确率会被头部类主导——最频繁类基线约 44.3%，模型偏向头部类也能拿到高准确率。宏观 F1（macro F1）对每个类别同等加权，能暴露尾部类别的识别短板，因此本项目采用双门槛：acc ≥ 85% 且 macro F1 ≥ 0.82。实测生产模型 acc 0.9963、macro F1 0.9678，双门槛均通过。

---

**用户问**：识别接口为什么返回 42902？

**回答**：根据[错误处理方案语料库](16-错误处理方案语料库.md)，42902 是系统的限流错误码。后端对识别接口实施了 60 次/分钟的限流保护，触发后返回 42902，属设计行为。

建议：
1. 降低调用频率，稍后重试
2. 自动化探针脚本请设置约 1.15 秒的请求间隔
3. 如确有高并发需求，可在 Nginx 层评估调整 limit_req 配置
