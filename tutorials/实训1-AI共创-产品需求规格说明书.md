# 实训1 基于AI共创的海瞳鱼鉴产品需求规格说明书（PRD）编写

## 一、实训目标

1. 掌握向 AI 清晰、准确提出海洋鱼类图像分类系统产品需求的方法与提问技巧
2. 学会定义海瞳鱼鉴六大核心功能模块（上传 / 预处理 / 识别 / 结果展示 / 历史 / 用户管理）与关键非功能需求
3. 理解产品需求规格说明书（PRD）的标准结构（全文 14 章 + 附录）与需求编号规范
4. 能够通过 AI 生成符合要求的海瞳鱼鉴 PRD 文档，并进行多轮迭代细化与章节审校
5. 掌握 PRD 硬性验收指标（测试集准确率 acc ≥ 85%、宏观 F1 ≥ 0.82）的核对方法

## 二、实训内容

### 1. 背景知识

简要介绍与本次实训相关的技术背景：

- **海瞳鱼鉴**：一款面向 23 类海洋鱼类的细粒度图像分类 Web 应用，采用 B/S 架构、前后端分离。用户在浏览器上传水下拍摄的鱼类图像，系统基于卷积神经网络完成物种识别，返回物种名称、置信度分数与 Top-5 候选概率分布，并展示该物种的形态特征与习性介绍。产品代号为 SeaPupil / seatong。

- **产品需求规格说明书（PRD）**：是产品开发过程中的权威基准文档，详细描述产品的功能边界、业务规则、技术架构、接口设计、验收标准等全部重要信息，是下游 UI/UX 设计、开发任务拆解、数据库设计、接口契约的直接依据。

- **AI 共创开发**：在产品研发过程中，借助大语言模型辅助完成文档撰写、方案设计、代码开发等工作。向 AI 提出需求时要清晰具体，先以 AI 生成内容为基础，再根据实际需要提出修改意见进行迭代优化。

- **六模块功能划分**：依据项目任务书，海瞳鱼鉴划分为六个功能模块，模块代号与职责如下：

  | 模块代号 | 模块名称 | 核心职责 |
  | --- | --- | --- |
  | UPLOAD | 图像上传 | 单图 / 批量上传、格式与大小校验、落盘 |
  | PREPROC | 预处理 | 图像解码、缩放至 224×224、归一化 |
  | RECOG | 智能识别 | CNN 推理、Top-5 候选、置信度与拒识阈值 |
  | RESULT | 结果展示 | 物种名称、概率分布、知识库介绍、免责声明 |
  | HISTORY | 历史记录 | 识别历史留存、筛选搜索、CSV 导出 |
  | USER | 用户管理 | 注册登录、游客试用额度、管理员后台 |

- **需求编号规范**：PRD 采用统一前缀区分需求类型，便于下游文档追溯与验收：

  | 类型 | 格式 | 示例 |
  | --- | --- | --- |
  | 功能需求 | `FR-<模块>-<两位序号>` | `FR-UPLOAD-01` |
  | 非功能需求 | `NFR-<类别>-<两位序号>` | `NFR-PERF-01` |
  | 业务规则 | `BR-<模块>-<两位序号>` | `BR-RECOG-03` |
  | 验收条件 | `AC-<FR 编号>-<序号>` | `AC-FR-UPLOAD-01-1` |

  非功能类别前缀：`PERF` 性能、`SEC` 安全、`REL` 可靠性、`COMPAT` 兼容性、`MAINT` 可维护性。

### 步骤2：向 AI 提出初始需求并生成 PRD 初稿

**操作内容：**

打开与 AI 的对话窗口，输入以下可直接复制的 Prompt，提出海瞳鱼鉴 PRD 的初始需求。该 Prompt 已明确产品形态、六模块划分、物种数量与两项硬指标，可显著降低 AI 理解偏差。

```text
你是一位资深产品经理。请帮我编写基于 CNN 的海洋鱼类图像分类系统的产品需求规格说明书，
产品名称为「海瞳鱼鉴」（SeaPupil / seatong）。

核心要求：
1. 产品形态：B/S 架构 Web 应用，前后端分离，浏览器即可访问。
2. 功能模块共六类，模块代号与职责如下：
   - UPLOAD 图像上传：单图/批量上传，单图≤10MB，批量最多9张
   - PREPROC 预处理：解码、缩放至 224×224、归一化
   - RECOG 智能识别：CNN 推理，输出 Top-5 候选与置信度，含拒识阈值
   - RESULT 结果展示：物种名称、概率分布、知识库介绍、免责声明
   - HISTORY 历史记录：留存、筛选搜索、CSV 导出
   - USER 用户管理：注册登录、游客免登录试用限3次、管理员后台
3. 分类规模：23 类海洋鱼类，细粒度图像分类。
4. 硬性指标：测试集总体准确率 acc ≥ 85%，平均宏观 F1（macro F1） ≥ 0.82，
   单图端到端耗时 ≤ 3 秒。
5. 文档结构：采用标准 PRD 结构，至少包含文档信息、产品概述、功能需求详述、
   页面与交互需求、数据需求、算法与模型需求、接口与集成需求、非功能需求、
   验收标准、风险与对策等章节。需求编号采用 FR-/NFR-/BR-/AC- 前缀。

请输出完整的产品需求规格说明书。
```

## 五、故障排除

### 问题1：AI 生成的 PRD 章节缺失或编号混乱

**现象：** 初稿缺少非功能需求、接口设计或附录，FR/NFR/BR/AC 编号不统一。

**解决方案：**

向 AI 明确下达结构化指令，要求其补齐缺失章节并统一编号前缀，然后重新统计验证：

```powershell

# 若计数明显偏低，回到步骤3继续要求 AI 补齐对应类型
```

### 问题2：准确率与宏观 F1 口径被 AI 混淆

**现象：** AI 将宏观 F1 写成加权平均 F1，或把 0.82 误写为 82%。

**解决方案：**

在 Prompt 中显式区分口径：宏观 F1（macro-F1）是各类别 F1 的算术平均、不按样本加权；阈值以小数 0.82 表示。用 PowerShell 核对文档中是否出现错误表述：

```powershell
Get-Content "E:\基于CNN的海洋鱼类图像分类系统-海瞳鱼鉴\04.实训指导书\AI共创过程文档\海瞳鱼鉴_PRD文档_练习.md" | Select-String "加权平均|82%"
# 预期输出: 若无命中则说明口径正确；若有命中需返回 AI 修正
```

### 问题3：端点数量或错误码数量不足 38 / 21

**现象：** 接口章节端点或错误码条目明显偏少，不满足下游开发任务文档的口径。

**解决方案：**

要求 AI 按六模块补全端点和错误码，例如上传、识别、历史、用户、管理、配置各补充必要端点；错误码覆盖 401（认证）、403（权限）、404（资源）、422（参数）、500（服务）等语义族。补充后重新计数：

```powershell

# 预期输出: 接近 38
```

**现象：** 练习稿误存到参考样例同名文件，或保存路径不在 AI共创过程文档 目录。
