### 2.1 端口口径纠正（本轮修订）

联调开始时发现**文档 / 配置 / 实际运行三者错位**：PRD §8.5、D8、产品原型均写前端 5173，
但 5173 已被同机另一项目（批小智）长期占用，实际 dev server 一直运行在 5180，
且后端 CORS 白名单不含 5180。已统一修订：

| 文件 / 文档 | 修订 |
|---|---|
| `frontend/vite.config.ts` | `port: 5173 → 5180`（strictPort 保持），注释说明 5173 被占原因 |
| `backend/app/core/config.py` | `frontend_origin` 默认值 → `http://localhost:5180` |
| `backend/app/main.py` | CORS 白名单加入 `localhost:5180` 与 `127.0.0.1:5180` |
| `docs/海瞳鱼鉴-PRD.md` §8.5 | 端口表 5173 → 5180 |
| `docs/海瞳鱼鉴-API接口契约.md` | 端口表与 CORS 说明同步 |
| `docs/海瞳鱼鉴-产品原型.html` | 部署说明文案同步 |

修订后**重启后端进程**使 CORS 生效，实测放行验证：`Origin: localhost:5180` 与
`127.0.0.1:5180` 均返回 `ACAO=<原值>` ✓（直连模式）。本机联调走 Vite 代理同源转发，不受跨域影响。

## 3. 验收级探针 `probe_acceptance.py`（本轮新增，83 项）

与既有探针的分工：既有四套覆盖「代码逻辑 / 结构审计 / 单端点专项 / live 冒烟」，
本探针补齐最后一层——**业务全链路逐环节断言 + PRD §9 性能分段 + 测试数据善后**（既有
`probe_live_server.py` 无 teardown，每跑一次遗留一个账号，本探针解决该缺口）。

### 3.1 拓扑一致性（18 项）

健康信封结构（code/request_id 与响应头一致）、X-Process-Time-Ms、DB PRAGMA、
模型状态、openapi 端点口径（32 路径 / 38 方法对，与 D8 §11.2 相等）、
前端可达且标题正确、**端口隔离**（5173 上确认不是本项目）、CORS 放行 5180。

### 3.2 游客全链路（16 项）

`GET /api/guest/quota` 字段名 `limit`（D8 契约）→ 上传**不消耗额度** → 连续识别 3 次成功
→ 识别**不落库**（record_id=None）→ Top-5 候选 rank 1..5 单调、置信度 [0,1]、
知识库形态/习性齐备、含模型版本号 → 第 4 次识别 **429 / 42901**。

### 3.3 注册用户全链路（32 项）

注册（双令牌）→ 登录 → 刷新令牌 → `/users/me`（is_guest=False、无游客额度）→
上传（22 ms）→ 识别 **fish_3 → idx=2 长棘光鳃鱼 conf=0.9282** → 落库 →
历史列表首位 + 字段齐备 + status ∈ success/interrupted → 详情四段
（record/image/species/candidates）→ Top-5 独立端点 → **导出 CSV**（UTF-8 BOM、
中文表头「中文名」、Content-Disposition 附件、非 JSON 信封）→ 缩略图（**JPEG**）→
原图字节 → **批量识别 3 张全部命中且逐张落库** → 单条记录删除（删后 40401）→
图像删除语义（见 3.5）。

### 3.4 鉴权与边界（8 项）

未认证 40101 · 伪造令牌 40101 · 不存在的图 40401 · 未知路由 40401 ·
参数缺失 40001（**非 FastAPI 默认 422**，全局异常处理器生效）· 物种越界 40401 ·
普通用户访问管理端点 40301 · **他人资源一律 40401**（防 ID 枚举语义实测正确）·
超 10 MB 上传 413 / 41301。

### 3.5 图像删除语义（实测澄清）

`DELETE /api/images/{id}` 的完整语义经本轮实测确认并写入断言：

| 场景 | 结果 | 设计依据 |
|---|---|---|
| 已产生识别记录的图（即便记录已软删除） | **42201**，提示改用历史删除入口 | 识别记录对图像是 CASCADE 外键，放行会连带删除用户历史（数据丢失） |
| 未识别的图，本人 | **200** | 正常清理 |
| 未识别的图，他人/游客 | 40401 | 防 ID 枚举 |
| 游客自己的图 | 不可删（归属为空，无法判定归属） | 由过期回收任务清理 |

由此确定**测试数据善后顺序**：先 `DELETE /api/admin/users/{uid}`（物理删除其识别记录、
image_asset 置 NULL），再按 id 删图像。本轮善后实测：删除账号 2 个 / 图像 30 张，零残留。

### 3.6 管理员口径

管理员账号口令 `Admin@12345` 命中（test_e2e 首轮初始化持久化），依赖管理权限的善后全部可用。
